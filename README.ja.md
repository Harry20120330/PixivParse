# PixivParse
[![License](https://img.shields.io/badge/License-Apache%202.0-blue.svg)](https://opensource.org/licenses/Apache-2.0)

[English](README.md) | [简体中文](README.zh.md) | 日本語

## 概要
PixivParse は軽量な **Tampermonkey ユーザースクリプト** で、Pixiv の作品を元画像の品質で解析・ダウンロードできます。Pixiv 作品ページにフローティングボタンを挿入し、以下を提供します：

- **元画像ダウンロード** — 個別・一括・ZIP の3経路すべてが `GM_xmlhttpRequest` に `Referer` を付与してホットリンク防止を回避し、`original` サイズの画像を取得
- **一括ダウンロード** — 1枚ずつ順次取得して保存、進捗表示と成功／失敗の件数付き
- **ワンクリック ZIP 圧縮** — [fflate](https://github.com/101arrowz/fflate) によるストリーミング圧縮、サーバー不要
- **統一された操作パネル** — 1枚ものと複数ページもので同じ画面構成を使い回し、ボタンは重要度に応じて3段階
- **多言語 UI** — 中 / 英 / 日 自動検出、手動切替可能
- **ダーク／ライトテーマ** — システムに従う・ダーク・ライトの3モード。

## プロジェクト構成
- `PixivParse.user.js`: 完全なスクリプトファイル（インストールに使用）
- `PixivParse.meta.js`: メタデータファイル（`@updateURL` の自動更新に使用）
- `LICENSE`: Apache License 2.0 本文
- `NOTICE`: サードパーティ帰属の表示
- `licenses/LICENSE-fflate.txt`: fflate MIT ライセンス
- `FastUpdate.sh` / `FastUpdate.ps1`: `PixivParse.user.js` から UserScript メタデータブロックを抽出して `PixivParse.meta.js` を再生成する保守スクリプト（Bash 版と PowerShell 版、出力バイトは同一）
- `.gitattributes`: 改行を LF に固定し、CRLF の作業コピーで上記スクリプトが誤動作するのを防ぎます

## クイックスタート

### 前提条件
- ユーザースクリプト対応ブラウザ：**Chrome / Edge / Firefox / Safari / Opera**（いずれも Tampermonkey のインストールが必要）
- 同一ブラウザで [pixiv.net](https://www.pixiv.net/) にログイン済み

### インストール
1. [Tampermonkey](https://www.tampermonkey.net/) 拡張機能をインストール。
2. 本リポジトリの生スクリプト URL を開く：
   - `https://raw.githubusercontent.com/Harry20120330/PixivParse/main/PixivParse.user.js`
3. スクリプトインストールページの「インストール」ボタンをクリック。
4. 任意の Pixiv 作品ページ、例 `https://www.pixiv.net/artworks/XXXX` にアクセス。

### 使用方法
1. ページ右端にフローティングの **解析** ボタンが表示されます。
2. クリックすると作品パネルが開きます。サムネイルの上、固定位置に**操作エリア**があり、その中のボタンは3段階に分かれています。エリアの位置は常に一定で、画像枚数によって変わるのは「どれが主操作か」だけです：

   | 段階 | 見た目 | 複数ページ (N > 1) | 1枚もの (N = 1) |
   |---|---|---|---|
   | 主操作 | アクセント色の塗りつぶし・太字 | ZIPで一括ダウンロード (N枚) | 原画をダウンロード |
   | 副操作 | アクセント色の縁取り | 全てダウンロード (N枚) | ZIPにする |
   | 個別 | 中性的、各サムネイルの下 | 画像 N をダウンロード | 表示しない（主操作が同じ処理を行うため） |

   - **ZIPで一括ダウンロード (N枚)** — 全画像を単一の ZIP にまとめます（1枚ずつ順番に取得、圧縮なしのストア方式）
   - **全てダウンロード (N枚)** — 1枚ずつ順次取得して保存します。途中で `ダウンロード中 i/N` を表示し、完了後に成功／失敗の件数を報告します
   - **画像 N をダウンロード** — 個別画像を保存
   - **タイトルをコピー** — 作品タイトルをクリップボードにコピー

   > 1枚ものに「全てダウンロード」を**あえて**出していない理由：それは「画像 1 をダウンロード」とまったく同じ関数・同じ引数を呼ぶだけです。見た目が同じで中身も同じボタンを2つ並べても、利用者は「どちらかに違いがあるのか」と迷うだけになります。
3. 上部バーのテーマ切替で 🌗 システムに従う / 🌙 ダーク / ☀️ ライト を、言語切替（🌐）で UI 言語を変更できます。どちらも選択内容は永続的に記憶され、テーマ切替時は再描画なしでスクロール位置も保持されます。

## 注意事項
- **ログイン必須。** スクリプトはブラウザセッション cookie を用いて Pixiv の `ajax` API を呼び出すため、pixiv.net にログイン済みである必要があります。
- **ZIP 圧縮とメモリ使用量。** fflate は CDN からオンデマンドで読み込まれます。CDN に到達できない場合、ZIP 圧縮は使用できません（個別ダウンロードは影響を受けません）。画像は1枚ずつ順番に取得され圧縮はストリーミングで行われますが、**完成した ZIP は全体がメモリ上に保持される**ため、ピーク時の使用量は元の画像の合計サイズとほぼ同じになります（エントリは圧縮せずストア方式で保存されます）。非常に大きなギャラリー（例：数百枚のフルサイズ PNG）ではメモリを大量に消費し、タブがクラッシュすることもあります。その場合は「全てダウンロード」をご利用ください。
- **リクエストの間引き。** ZIP 圧縮も「全てダウンロード」も**1枚ずつ順次**取得するため、同時に走るリクエストは常に1つだけです。1.1.2 以降、「全てダウンロード」は 300ms 間隔の並行トリガーではなく逐次 `await` になりました。各画像をいったん Blob として取得してからブラウザに保存する方式に変わったため、並行させると大きな画像が複数同時にメモリへ乗り、ブラウザの複数ダウンロード警告も誘発しやすくなります。それでも、繰り返し解析したり一度に大量取得したりするのは避け、Pixiv に負荷をかけないよう心がけてください。
- **サイレント失敗の廃止。** ダウンロードは成功・フォールバック・失敗のいずれも画面に通知します。失敗時は原因（HTTP ステータス／タイムアウト／ネットワークエラー）を明示し、詳細はコンソールに出力されます。
- **サーバーなし。** すべての操作はブラウザ内で完結し、アカウント・キー・バックエンドは不要です。
- **静止画のみ対応。** うごきらす（アニメーション作品）は解析できません。空のギャラリーを表示する代わりに、パネルにその旨を明示します。静止画のイラストと複数ページのマンガはどちらも対応しています。
- **ファイル名のサニタイズ。** 作品タイトルはダウンロードのファイル名と ZIP 内のフォルダ名に使われるため、ファイル名に使用できない文字（`\` `/` `:` `*` `?` `"` `<` `>` `|`）と制御文字はアンダースコアに置換し、先頭・末尾のドットと空白は除去し、長すぎるタイトルは 120 バイトで文字境界を保持して切り詰め、`CON` や `NUL` などの Windows 予約デバイス名には接尾辞を付けます。これによりダウンロードのサイレント失敗や、タイトルが `..` のような場合に ZIP 解凍が対象フォルダの外へ書き出す問題を防ぎます。

## 設定
スクリプト冒頭付近のこれらの定数は編集前提です。変更後は Tampermonkey でスクリプトを再読み込みしてください：

| 定数 | 既定値 | 説明 |
|---|---|---|
| `SHOW_ZIP_FOR_SINGLE` | `true` | 1枚もの作品で「ZIPにする」を表示するか。ZIP 内は `作品名/001.jpg` の構成になるため、作品単位で整理したい場合に便利です。余計なら `false` に |
| `FILENAME_MAX_BYTES` | `120` | ファイル名のバイト上限。`_000.png` / `.zip` の接尾辞分の余裕を含みます |
| `METADATA_TIMEOUT_MS` | `20000` | メタデータ API のタイムアウト（ミリ秒） |
| `CUSTOM_HEADERS` | `Referer: https://www.pixiv.net/` | ホットリンク防止を回避するためのヘッダー。通常は変更不要 |

ボタン3段階の外観は `BTN_VARIANTS` で、配色は各テーマの `--pp-primary-*` / `--pp-secondary-*` 変数で定義されています。雰囲気を変えたい場合はこの2箇所を編集してください。

## トラブルシューティング
- **「画像をダウンロード」を押しても無反応（v1.1.0 以前）：** 旧版の個別ダウンロードは `GM_download` を呼んでいました。これはブラウザのダウンロード API に処理を委譲するもので、**カスタムリクエストヘッダーを付与する手段がありません**。一方 `i.pximg.net` は `Referer` の無いリクエストに一律 403 を返すため、ダウンロードはサーバー側で失敗し、Tampermonkey はコールバックもエラーも返しません。結果として「押しても何も起きない」ように見えます。1枚ものの作品が最も深刻で、その場合は ZIP も「全てダウンロード」も描画されず、パネルに残る唯一のボタンが壊れている状態でした。1.1.1 で `GM_xmlhttpRequest` に `Referer` を付けて Blob を取得してから保存する方式（ZIP と同じ経路）に修正済みです。更新してください。
- **ステータスコード付きの失敗通知が出る：** パネルが理由を報告するようになりました。403 なら多くはセッション切れです。pixiv.net にログインし直してください。タイムアウトならネットワークを確認してください。
- **フローティングボタンが表示されない：** ページ URL が `https://www.pixiv.net/artworks/*` にマッチし、スクリプトが有効であることを確認してください。
- **画像が読み込まれない：** pixiv.net にログイン済みで、ブラウザから到達可能であることをご確認ください。
- **圧縮に失敗し、fflate が見つからないと表示される：** CDN の `@require` 読み込みに失敗しています。ネットワークを確認するか、ページを再読み込みしてください。
- **自動更新が効かない：** `@updateURL` は `PixivParse.meta.js` を指しています。上記の生 URL からスクリプトがインストールされていることを確認してください。

## 更新履歴

### 1.1.2
- 1枚ものと複数ページもので操作エリアを統一し、`if (data.images.length > 1)` の分岐を削除しました。この分岐こそが、1枚ものの作品を誰も見ないコードパスに置き続けていた原因です。
- ボタンを主操作／副操作／個別の3段階に。以前はすべてのボタンが同一の外観で、`--pp-accent` はタイトルの横にある 8px の小四角にしか使われていませんでした。
- 1枚ものの作品では、主操作と重複する個別ボタンを描画しなくなりました。
- 「全てダウンロード」を逐次 `await` に変更し、進捗表示と実際の成功／失敗件数を追加。ブロッキングな `alert()` を廃止。
- 設定定数 `SHOW_ZIP_FOR_SINGLE` を追加。
- 中／英／日の文言を追加：`downloadOriginal`、`packZipSingle`。

### 1.1.1
- **個別ダウンロードが無反応になる問題を修正。** リクエストヘッダーを付与できない `GM_download` への依存をやめ、`GM_xmlhttpRequest` に `Referer` を付けて Blob を取得してから保存する方式に変更しました。
- `GM_download` は最後の手段のフォールバックに降格。
- 成功・フォールバック・失敗のすべてに toast を表示し、サイレント失敗をなくしました。
- 中／英／日の文言を追加：`downloadingSingle`、`dlStarted`、`dlFailed`、`dlFallback`、`batchDone`、`batchDoneWithFailed`。
